# 文旅智能体 · 用户旅程与交互规范（D1 / B 线交付）

> 目标：把「政务导办」的信息架构，最小改动地换成「吉林文旅行程助手」。
> 约束：四 tab 结构与 `/api/chat` 契约不动，只换语义、加一张行程卡片页。

## 一、三个真实场景（对应 1.1 场景价值 12 分）

| 场景 | 用户 | 一句话诉求 | 现有产品给的 | 我们给的 |
|---|---|---|---|---|
| S1 本地周末 | 长春 35 岁家长，带 6 岁孩子 | "周六周日两天，开车两小时内，孩子能跑能玩" | 一堆景区列表 | 2 天行程卡片：上午/下午各 1 个点 + 雨天备选 + 是否需要预约 |
| S2 银发结伴 | 62 岁退休夫妻，不会用复杂 App | "去长白山怎么走，累不累" | 官网攻略长文 | 大字版 3 步：怎么去→到哪买票→哪些路段要爬 |
| S3 外地研学 | 哈尔滨老师，带 20 人团 | "红色+高句丽，两天怎么排不赶" | 需要自己拼 | 供给约束可见：每点建议停留时长 + 周一闭馆提示 + 团体预约入口 |

**共同点**：用户要的不是"介绍景点"，是"替我排一个能执行的顺序"。这就是"智能体"和"搜索框"的分界线。

## 二、核心任务（JTBD）

> 当我想在吉林玩 1–3 天时，我希望给出「几个人、几月、想要什么感觉」，就拿到一条**顺序合理、有官方依据、能直接照着走**的行程，而不必在五个 App 之间来回对照。

判断标准（D7 走查时用）：
- 从打开到看见第一张行程卡片 ≤ 60 秒、≤ 3 次点击；
- 卡片上每个点都能点开"依据"，看到官方来源与核对日期；
- 断网时仍能演示，不白屏。

## 三、信息架构（四 tab 语义平移）

| tab id | 原语义 | 新语义 | 变化 |
|---|---|---|---|
| `home` | 首页 | **首页**：一句提问 + 三个一键脚本 | 换文案与 hero，不动结构 |
| `services` | 服务六宫格 | **发现**：冰雪 / 山水 / 民俗 / 遗址 / 湿地 / 城市 | 只换类目数据 |
| `news` | 资讯 | **时令**：本季节庆、花期、雾凇概率、闭馆公告 | 数据源换成 calendar 表 |
| `profile` | 我的 | **我的**：出行偏好（复用个人信息弹层） | 加"同行人/预算档/节奏"，滚轮逻辑不动 |

`/api/chat` 请求体与响应字段保持不变，只在 `actions` 里新增一种 `itinerary`（打开行程卡片），前端按白名单过滤，未知动作忽略。

## 四、主流程（新用户第一次可用）

```
打开首页
  ├─ 城市胶囊（默认长春市，可切换 9 市州）
  ├─ 输入框："想去哪、玩几天、和谁一起"
  └─ 三个卡片：冰雪 2 日 / 民俗 2 日 / 湿地 1 日
        │
        ▼  点击或输入
  对话面板（底部弹出，与现有 AI 胶囊一致）
  ├─ 状态：空闲 → 识别中（≤1s）→ 生成中（骨架屏）→ 结果
  └─ 结果 = 一段 100–220 字讲解 + 1 个"查看行程"按钮 + N 个官方入口
        │
        ▼  点"查看行程"
  行程卡片页（全屏 sheet）
  ├─ 顶部：天数 / 片区 / 同行人 / 预算档
  ├─ 时间轴：Day1 上午 · 节点 · 建议停留 · 一句理由
  ├─ 每个节点右侧「依据」→ 抽屉：来源名 + URL + 核对日期 + 提示语
  ├─ 底部：行前清单（预约 / 证件 / 衣物 / 天气）+ 导出长图 + 回到对话
  └─ 空/错态：无匹配 → 给 2 个替代片区，而不是"抱歉"
```

## 五、页面与状态清单

| 页面 | 状态 | 关键交互 | 失败时 |
|---|---|---|---|
| 首页 | 默认 / 已选城市 / 长辈模式 | 城市胶囊、一问三卡 | 城市未识别 → 用默认城市并提示"已按长春市推荐" |
| 对话面板 | 空闲 / 思考 / 流式（可选）/ 完成 / 超时 / 错误 | 追问、语音、回车发送 | 20s 超时 → "换一种问法"或"看示例" |
| 行程卡片 | 生成中骨架 / 完整 / 部分（某节点缺数据） | 点节点看依据、滑动换天、导出 | 节点缺 official → 显示"该点暂无官方入口"，不编链接 |
| 依据抽屉 | 打开 / 关闭 | 点 URL 用**系统浏览器**打开，非站内跳转 | 域名非白名单 → 前端拦截并提示 |
| 我的 | 默认 / 已填偏好 | 复用个人信息滚轮弹层 | 无存储权限 → 只本次会话生效 |

## 六、交互与文案规范

**时间预算**：点击 → 首字 ≤ 3s；识别意图 ≤ 1s（本地规则，不走模型）；整卡 ≤ 8s。超时阈值 20s（沿用现有 AbortController）。

**加载态**：用骨架屏（3 行灰条 + 1 个卡片轮廓），不用转圈；文案"正在排顺序…"而不是"加载中"。

**错误分级**（决定用户下一步，而不是只报错）：

| 情况 | 文案 | 出口 |
|---|---|---|
| 模型空返回 | "这次没生成出来，换一种问法试试？" | 重试 / 看示例 |
| 限流 429 | "问得有点快，30 秒后再试" | 倒计时按钮 |
| 无匹配知识 | "这个点还没核对到官方信息。要不要看看雾凇岛或六鼎山？" | 2 个替代项 |
| 断网 | "现在是离线模式，看到的是示例行程" | 恢复后自动重试 |

**微文案原则**：动作用动词（"查看行程""换一天"），不用"确定/取消"；不用"亲""宝子"；长辈模式句子更短、每句一个动作。

## 七、无障碍与长辈模式（1.4 演示体验的隐形加分项）

- 触控区 ≥ 44×44px，滚轮项 44px（与现有 `profile.js` 的 `STEP=44` 一致）；
- 长辈模式：正文 17px→19px，次要文字对比度 ≥ 4.5:1，隐藏装饰动效；
- 全流程键盘可达，focus 可见；`aria-live` 播报"正在生成 / 已生成";
- 语音：现有 TTS 复用到行程卡片（"朗读今天行程"），语音输入沿用 Web Speech，不支持时降级为键盘提示。

## 八、演示态设计（对应 1.4 演示效果 18 分）

现场 40 分钟里，**不能有 1 分钟花在等模型或找入口**。因此：

1. **三个一键脚本**（首页卡片，点击即出卡片，不经过输入框）：冰雪 2 日 / 民俗 2 日 / 湿地 1 日；
2. **演示开关**：`?demo=offline` 或我的页开关 → 全部走内置样例，不调模型；
3. **可解释动作**：任意节点 → 依据抽屉（30 秒内能讲清"我们凭什么这么说"）；
4. **失败可控**：模型慢于 8s 自动切样例并提示"已切换到演示数据"，评委看不到卡死。
