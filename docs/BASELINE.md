**项目类型**：2026 吉林省高校大学生机器人大赛「吉林特色产业智能体应用开发」参赛项目  
**基线日期**：2026-11-14  
**文档状态**：v1.1（项目与交互规范；以实际部署和测试结果标记实现状态）  
**目标**：开发一个真正可安装、可现场运行的吉林省政务信息与 AI 办事辅助应用，以比赛演示为交付优先级，同时保证合理的速度、稳定性和代码质量。

## 2. 典型业务场景与比赛演示脚本

**场景 A：老年居民不会办事（主要）**

1. 用户打开 Windows 桌面应用，开启「长者关怀」，选择「长春市」。
2. 用户问：「退休以后养老金相关信息应该去哪里查？我不会操作。」
3. AI 先检索已验证资料；如当前资料不足，明确提示需到官方站点确认，不编造办理条件。
4. AI 给出「打开应用内社保事项」「查看操作步骤」「打开吉林官方政务入口」等按钮。
5. 用户点击站内按钮，应用导航到正确的办事指南；清单可勾选，外部办理跳转系统浏览器。

**场景 B：普通居民跨地区咨询**

1. 用户将地区由长春改为吉林市，输入「居住证怎么办」。
2. AI 说明当前选定地区、检索到的来源，以及可能存在的地区差异。
3. 应用打开符合该地区标注的事项；若没有经核实的具体区县步骤，不捏造地址、时限或材料。

**场景 C：基层公务人员政策检索**

1. 将应用视角切换为「政务协作」。
2. 用户询问某项公开政策的概要及出处。
3. AI 提供简明摘要、文号（仅在来源提供时）、发布日期及官方原文；强调这是辅助检索而非具有行政效力的解释。

现场演示至少实际运行以上 2 个场景，并展示一次非预设提问及一次知识库内容微调/更新过程。不能用录屏替代实际操作。

## 3. 技术架构（单体前端 + 轻后端）

```text
Windows 安装包（Tauri 2）／可复用 Android 壳
└── Vue 3 + TypeScript + Vite
    ├── Auth / Profile（Supabase SDK）
    ├── Home / Region / Services / News / Assistant / Settings
    ├── 服务与政策的本地轻缓存（非敏感内容）
    └── API Client → HTTPS
                       │
                  Cloudflare Worker（单一 API 网关）
                    ├── 验证用户身份、限流、输入校验
                    ├── 读取版本化的政务资料索引
                    ├── 事项/新闻检索与引用过滤
                    ├── 组合上下文 → Workers AI → 结构化输出校验
                    └── 返回文本、来源和可执行的站内/站外动作
                       │
                  Supabase Auth + PostgreSQL
                    └── profiles / saved_items（按需）
```

**实施说明**：本节为中期目标架构，不能当作当前已完成的系统。现运行工程是轻量 PWA + 单一 Cloudflare Worker，尚未接入 Supabase，也未迁移到 Vue/Tauri。

**为什么这样分层**：使用成熟认证系统避免自己保存密码；把密钥和模型调用放在服务器端，客户端不会暴露密钥；政务资料版本化并可审计；前端与桌面壳解耦，三人可以并行开发。  
**首版不用**：自建 ECS、Kubernetes、Redis、向量数据库、消息队列、复杂爬虫、多个 AI 模型串联。  
**包体与系统前提**：Tauri Windows 构建需要 Rust、Microsoft C++ Build Tools 和 WebView2；Android 打包额外依赖 Android Studio/SDK/NDK。先完成 Windows 演示闭环，再验证 APK。

## 4. AI 与应用深度联动契约

AI **不是聊天窗口的替身**，必须理解当前界面、所在地区、用户视角和可用事项，输出可操作而非纯文字的建议。

**处理链**：用户输入 → 读取允许的页面上下文 → 从官方资料目录检索 → 判断信息是否足够 → 调用云端模型生成通俗解释 → 后端验证引用和动作 → 前端呈现按钮 → 用户主动点击执行。  
**首版检索方案**：结构化 JSON + 标题/关键词检索，在有限的高质量资料上做轻量检索增强。暂不引入向量库；只有实测检索效果不足时再评估升级。  
**工具能力（逻辑功能，不是额外服务）**：`search_services`、`search_policies`、`get_region_context`、`get_service_steps`、`recommend_app_action`。模型只建议动作，真正执行必须经应用校验且由用户点击。

### 4.1 API 请求契约（冻结）

**中期目标接口**：`POST /api/v1/assistant/chat` ；`Authorization: Bearer <Supabase access token>`。**当前已运行接口**：`POST /api/chat`，请求字段为 `question / region / history`，当前不具备 Supabase 登录；现行响应为 `text / actions / sources`，动作类型为 `guide / official / tab`。禁止将目标 API 误认为已经实现。

```json
{
  "message": "老年人如何查养老金？",
  "regionCode": "220100",
  "audience": "resident",
  "context": {"pageId": "home", "serviceId": null},
  "history": [{"role": "user", "content": "..."}]
}
```

说明：`audience` 只能是 `resident` 或 `staff`；`history` 仅取最近有限轮次；敏感个人信息不进入检索库或日志；接口严控输入长度、频率及总模型额度。`regionCode` 是应用内区域选择代码，不代表用户法定户籍。

### 4.2 API 响应契约（冻结）

```json
{
  "reply": "可以先查看吉林官方政务服务入口。具体条件以原文为准。",
  "evidenceLevel": "grounded",
  "sources": [
    {"title": "吉林省政务服务平台", "url": "https://zwfw.jl.gov.cn/", "checkedAt": "2026-11-13"}
  ],
  "actions": [
    {"type": "navigate", "label": "查看社保事项", "target": "/services?category=social-security"},
    {"type": "open_url", "label": "前往官方政务平台", "target": "https://zwfw.jl.gov.cn/"}
  ],
  "requestId": "generated-on-server"
}
```

`evidenceLevel` 取 `grounded` / `limited` / `unknown`。`actions.type` 只允许 `navigate`、`open_url`、`show_steps`。前端只处理白名单路由；后端只返回在**已审核来源清单**中的官方 URL，禁止模型生成任意网址或脚本。API 错误使用明确 HTTP 状态码及 `{error:{code,message},requestId}`；AI 超额或不可用时应明确告知，不能伪造 AI 回复。

### 4.3 资料可信性规则

1. 只录入可核验的政府站点、政府公开文件或已确认权威服务入口。
2. 每条事项保留：`id / title / regionCodes / category / audience / summary / steps / materials / sourceIds / lastCheckedAt`；不知道的字段标记「以官方办事指南为准」，不猜测。
3. 每条新闻保留：`id / title / publishedAt / publisher / originalUrl / regionCode / lastCheckedAt`。资讯显示其**发布日期**，不能标成“实时”。
4. AI 答复涉及政策依据、办理条件、材料、时限、地点、费用时必须有来源；未检索到来源就直接说明不足。
5. 禁止以 AI 解释取代官方行政答复；不自动为用户提交申请或访问需要授权的政务账号。

## 5. 页面与视觉基线

- **主导航**：当前手机端为首页、办事、资讯、我的四栏；AI 助手由悬浮入口打开。未来桌面导航根据实测决定。
- **视觉方向**：深政务蓝 + 松花江青 + 温暖灰白；清晰、现代、可信，不模仿吉林省人民政府官方界面和印章。
- **字体**：系统中文无衬线；正常模式正文目标约 15–16px，适老模式约 19–21px（按实际设备测试）。
- **可访问性**：显著的对比度；主要触控目标建议至少 44×44px；避免只用颜色传达信息；为复杂事项使用「一步一步」视图。
- **应答卡片**：AI 回复分为「简明结论」「依据来源」「下一步操作」三层；链接显示来源域名并明确将在浏览器打开。
- **账号与地域**：首次使用完成地区选择；公众内容允许游客浏览，AI 交互和收藏在正式流程中要求登录。即便有游客模式，也不得绕过后端 AI 限流。

## 6. 数据结构与存储界限

| 数据 | 存储位置 | 必须约束 |
|---|---|---|
| 认证信息 | Supabase Auth | 不自建密码表，不保存明文密码 |
| `profiles` | Supabase Postgres | `user_id`、`region_code`、`audience`、`elder_mode`、`created_at`；启用 RLS |
| `saved_items`（可选） | Supabase Postgres | 收藏用户 ID + 官方来源 ID；RLS 只允许本人操作 |
| 政务事项与新闻元数据 | Git 仓库内版本化 JSON，部署到 API 或静态资源 | 每次更新须人工核对来源、日期和地区范围 |
| 当前聊天上下文 | 客户端内存；仅发送必要最近消息 | 默认不在数据库保存完整对话，避免无谓收集个人信息 |
| AI 模型密钥 | Cloudflare Worker 环境密钥 | 不写入仓库、不放入安装包 |

**角色说明**：`staff` 是资料浏览偏好，**不是公务员身份验证、权限或官方授权**。应用统一展示「非官方政务服务辅助工具，最终以主管部门正式信息为准」。

## 7. 性能、可靠性与安全基线

**这些是研发验收目标，不是已经测得的性能，不得对外宣称达成。** 用目标设备和稳定网络实测，记录 P50/P95，发现未达标先定位瓶颈再优化。

| 指标 | 首版目标 | 测量方式 |
|---|---|---|
| 桌面首屏可交互 | 热启动 ≤ 2 s | 10 次启动计时，取 P95（目标设备） |
| 应用内普通页面切换 | P95 ≤ 200 ms | 路由点击到主要内容可见 |
| 本地事项关键词检索 | P95 ≤ 300 ms | 对固定资料集连续运行 30 次 |
| 普通 API（不含 AI） | P95 ≤ 1.0 s | 稳定网络请求计时 |
| AI 首次可见结果 | 目标 ≤ 5 s | 云模型受网络与配额影响；超时给明确状态提示 |
| AI 完整答复 | 目标 ≤ 20 s | 记录云端延迟，不因一次失败无限重试 |
| 运行稳定性 | 完整连续演示 30 min 无阻断性故障 | 两台设备复现并记录问题 |

**性能原则**：页面先显示骨架和缓存元数据，网络请求异步处理；图片懒加载；手工精选新闻避免实时抓取；一次用户提问原则上调用一次主模型；不引入多模型代理链；客户端限制重复提交；对官方数据实现按版本缓存。  
**安全原则**：所有 API 使用 HTTPS；Worker 验证真实的 Supabase 身份令牌，不信任前端传来的用户 ID；Supabase RLS 必须开启；接口校验参数；对公共 API 和 AI 配额限流；官方链接域名白名单；避免把政策资料中的外来文本当成系统指令；不存身份证号、银行卡号、政务账号密码。  
**网络中断**：本地静态事项、已缓存资讯与站内导航可继续用；云端 AI 必须明确显示「当前需要网络」，不把静态搜索伪称为大模型答复。

6. 如发生冲突，由 A 依据基线和实际运行结果定版；每次新增需求修改版本号与决策记录。

## 12. 用户可见文案规范（v1.1 新增，强制）

**目标：所有面向普通用户的页面、弹窗、状态提示、AI 回复和按钮都应呈现可直接使用的正式产品文案，而不是开发者的过程记录。** 本条约束不禁止在 Git 提交、测试记录、开发文档中准确描述研发状态。

- **禁止过程性用语进入常规界面**：例如“学生竞赛原型”“演示版本”“测试功能”“开发中”“待完善”“预计支持”“本 Demo”“v0.x 交互原型”“假数据”“尚未制作”。内部状态只能写进项目文档、测试报告或调试面板。
- **不掩盖真实功能边界**：尚无账号系统时，不得显示已注册账号；没有实时政务新闻时，明确展示“官方资讯入口”，不得伪造新闻时间和报道；联网失败可以简短提示“连接失败，请重试”。必要的事实提示不是要删除的过程性措辞。
- **非官方身份必须清楚，但不反复打断阅读**：在“关于/设置”与必要的服务入口处写“独立信息服务，非政府官方应用”，并说明政务办理以官方发布为准。**不得假冒官方政府应用**，不使用未经授权的政府标志。
- **政务答复原则**：首句直给结论；办事步骤简洁；文号、资格、金额、截止日期等必须有真实来源；门户链接不可冒充具体事项链接；AI 不声称查过未实际访问的页面。
- **UI 验收**：搜索并人工检查所有可见文案；禁止一次性堆叠多条免责声明、重复状态和多余的技术术语。每次发布前至少核对首页、服务、资讯、设置、AI 空态、AI 错误态、引导弹层。

## 13. AI 思考状态与动态规范（v1.1 新增，强制）

- 发出云端请求后在回答区出现 **“吉小知正在思考…”**，使用微型蓝色光体呼吸、环形柔光和小圆点循环。整体节奏约 3.6 秒，缓慢连续，不采用生硬跳帧或背景毛玻璃。
- 该状态**仅表示请求正在处理**，不展示或编造模型内部的思维链。当前模型运行时关闭推理模式；不得以“已检索 32 个网站”“正在审查 5 条法规”等未经真实工具事件证明的话术包装动画。
- 收到正文后替换等待状态；AI 回复沿用渐进词组显示。允许“显示全文”，不得为视觉效果刻意延迟真正的答复。
- **保留对话弹层 DOM**，正常消息更新不重新播放整个弹层入场动画，避免输入焦点丢失及内容跳动。
- 尊重 `prefers-reduced-motion` 与长辈模式，禁用不必要的循环动画。背景保持清晰；触摸与键盘焦点反馈需明显但不显示突兀的直角蓝框。
- 性能验收：等待态进入/退出不引起弹层重建；关闭窗口取消请求和动画；320/390/430px 宽度不横向溢出；状态区域支持屏幕阅读器。

## 14. Agent 能力取舍与路线（v1.1 新增）

**决策：增加“受控办事 Agent”的比重，但不做通用手机控制 Agent，也不引入多智能体框架。** 让 AI 能理解场景、提出站内操作建议，用户点击后执行安全动作；不是自行操作系统级权限、第三方账号或政府后台。

| 功能 | 当前 v0.5.4 状态 | 下一阶段优先级 | 执行约束 |
|---|---|---|---|
| 当前地区上下文 | 已支持 | 保留 | 不等于真实户籍或地理位置 |
| 应用内办事指南 / 外部门户按钮 | 已支持 | 保留并完善 | 白名单校验，用户点击执行 |
| 当前页面上下文（页面名/可用操作） | 未接入 AI 请求 | 高 | 只传非敏感页面标识 |
| 查询已验证服务事项、读取步骤 | 关键词检索仅门户级 | 高 | 回传来源、适用地区与核验信息 |
| AI 指引切换地区、切换页面 | 当前有限静态动作 | 高 | 显式动作白名单；影响地区时需确认 |
| 多轮问答中的任务清单 | 未实现 | 中 | 不存敏感身份信息 |
| 模型函数调用（Tool Calling） | 未启用 | 中 | 仅少量只读工具，限制调用步数和超时 |
| 后台驻留、跨应用自动点击、无障碍控制、政务代提交 | 未实现 | 不做 | 与首版比赛价值不匹配，安全与权限成本过高 |

**Agent 最小闭环**：用户提问 → 获取地区与当前页面 → 匹配已审核的事项 → AI 解释并提出 1～3 个下一步动作 → 用户确认/点击 → 应用导航、展示步骤或打开官方入口。不得把模型输出当作可直接执行的脚本。

**接口治理**：短期不破坏现行 `/api/chat`，如需新字段，新增可选 `context: {pageId, serviceId}` 并增量测试。后端只读工具建议从 `search_services`、`get_service_guide`、`get_current_region` 三项开始；站内动作由前端执行，政府官网链接必须使用审核过的域名/路径。一次问答默认仅一次主模型调用，不因简单问答启用多轮代理链。

**发布判定**：只有 Agent 实际调用工具并返回对应结果后，才能在产品说明中称“可执行任务”。当前版本仅能提供安全的站内动作建议，不能宣称已具备系统级手机 Agent 权限。用户不得被要求提供政府账号密码、短信验证码或身份证号给本应用。
