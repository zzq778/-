# 吉政知行：智能体赛项对齐与 v0.7 迭代基线

## 核心定位（以 2026 年 11 月赛事规则为准）
作品定位：**吉林省政务任务智能体**。面向吉林省居民，尤其是中老年用户，让用户使用自然语言表达办事目标，由 AI 决定如何调用经过核验的事项索引、导办步骤和官方门户工具，输出可执行的办事计划与站内引导。

不再以“六个政务服务入口 + 一个聊天助手”作为主价值展示；服务分类保留，但承担被 Agent 调用的工具与人工备用导航作用。

## 赛事强约束
- 政务与公共服务是规则列明的参考选题。报名选题须真实、明确，审批后原则上不得更改；本次修改仅调整产品能力主轴，不改变选题领域。
- 2026-11-23 24:00 是所提供 2026 年 11 月版规则写明的报名截止时间，须留意赛项信息平台新通知。
- 现场 60 分钟（实操 40 分 / 汇报 20 分），须用自带电脑运行实际作品，并按评委要求现场微调知识库、提示词、工具；不能用录屏代替。
- 评分：场景 12、智能体和工作流 18、知识和数据 12、演示和交互 18、创新 10、汇报表达 20、合规安全 10。
- 规则提供“指定竞赛平台 LXClaw”，同段又称“推荐平台”。不能擅自推定纯自建 Cloudflare 系统等价合规；需要赛项执委会明确核对必要平台条件及参赛环境约束。
- 现场禁止场内外信息交互，且要求能够处理网络中断。不得未经核实地假设现场可持续调用外部付费 API。网络能力需向赛方确认；如不允许外网，则必须按许可的环境/平台重做模型后端。

## 产品关键演示闭环

用户："我是长春的老人，不会办养老资格认证，你带我办。"

1. 识别用户所在市州和办事需求（模型处理问询与上下文）。
2. 模型选择 `search_services` 查询本地事项索引。
3. 在查询匹配后，工作流自动读取 `read_service_guide`，取得本地已核对的导办步骤。
4. 生成自然语言答复 + 三步任务卡 + 实际工具调用记录。
5. 用户点击 "查看养老指南" 打开应用内指导；点击官方门户入口自行核实、继续办理。
6. 如缺少政策依据，不能猜测额度、资格或具体材料，应说明资料边界并追问必要事项。

**当前不支持**：自主登录政府网站、提交申请、获取个人医保账户、办理实绩查询或读取最新政策全文。未经真正联调，不宣称具备这些能力。

## v0.7 当前已完成
- 原有移动端首页、语音/PWA、附件、Cloudflare 与 DeepSeek 路线保留。
- `src/agent.mjs` 提供模型 Function Calling、明确工具白名单、参数校验、最多三次工具调用、单次最终生成；避免无限循环、隐式越权和虚假操作记录。
- `mode=agent` 的文本聊天调用进入该工作流。携带图片/文件仍走已实现的多模态流程，不与新工具流程强行混合。
- 前端显示已调用的工具记录、三步事项卡和可点击指南，展示的是外部可核实的工具动作而非内部思考文本。
- 原版 JSON `/api/chat` 无 `mode` 的兼容路径仍在；现网 `main` 不变。
- 所有官方按钮由后端限定、经过核验的官方门户白名单产生，而不是解析模型自由生成的 URL。

## 优先级和下一阶段验收
1. **最优先：核实 LXClaw 要求并完成赛方允许的运行架构**。如果指定平台确为必用，则在 LXClaw 中实际配置知识库、工具调用和可现场演示的工作流，手机端只做呈现与交互。
2. **知识库不是六条固定主题**：团队整理每个事项的权威原文、发布日期、适用地区、条件/材料、核验时间，保留版本信息，建立可随赛场要求更新的检索数据；展示真实检索证据和无结果情况。只有实现后才可称为 RAG。
3. **至少 3 条真实闭环**：养老资格认证、医保办事指南、身份证换领，每条有正常/缺少信息/无依据三类现场实测。
4. **现场可重配置**：支持调整提示词、导入新的政策资料并实际影响后续检索结果，且可以明确说明每一次工具调用来源。
5. **合规和成本**：限制支付 API 访问、避免敏感材料、严禁假装已经办理成功；根据赛场网络条件设计可靠演示环境。

## 三人分工建议
- 前端/集成：手机端对话、任务卡、来源/工具记录、导办路径展示与联调。
- Agent/平台：模型工具调用、LXClaw 集成、工作流安全与接口测试。
- 知识/测试：官方政策取证、可信检索库、评委随机问题集、测试结果与合规记录。

保持主分支 `main` 稳定、功能在 `feature/*` 开发，经 PR 审查测试后才进入正式发布。

## v0.7.1：跨会话导办清单（2026-11-14）
- Agent 返回的事项计划由用户主动点击“保存为导办清单”，而不是自动创建政府业务申请。
- 单设备最多保存一份通用导办计划：事项 ID、地区、三条已验证来源范围内的通用步骤、阅读标记。不存储用户原话、聊天历史、身份证号码或政府账号；用户可以随时清除。此计划不跨设备同步。
- 首页和“我的”可继续查看，逐步标记“已了解”；全部标记只表示阅读完成，绝不能展示“政府已办结”。
- 改变地区后仍保留原清单，但明确提示地区差异，不再向 Agent 传递不适用的新地区任务上下文。
- 点击“继续问吉小知”会预填下一问，用户确认发送后服务器仅接受经过校验的事项 ID 与 0-3 的已了解数量；这是对话上下文，不是政府后台查询。
- 不引入数据库、注册或第三方登录。未来有真实任务同步需求时先重新评估隐私与身份认证成本。
- LXClaw 暂停开发（产品决策），其比赛合规风险仍保留在单独文档中；不能认为已经核实允许不使用该平台。
- 发布门槛：原有 Node 测试、320/390/430px 浏览器模拟测试，以及真实线上模型联调。`main` 暂时不更新。
